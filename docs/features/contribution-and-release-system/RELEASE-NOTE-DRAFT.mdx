This release sets up a complete path from writing a commit to deploying in production, built around one idea: the squash commit message is the only thing written by hand, and everything else derives from it.

Until now, the "why" of a change lived in a PR comment or a chat thread — if anywhere — and most projects had no notion of version: everything merged went to production at the same pace. From this release on, every PR is squash-merged into a single curated commit (Conventional Commits, checked locally by lefthook and in CI on the PR title and description). release-please reads those commits and maintains a Release PR: next version, generated `CHANGELOG.md`. A human merges it — that is the release gate. The tag then builds versioned Docker images for **every** runnable app (API, web-spa, web-ssr), and the new **Promote** workflow sends a chosen version to one environment in one click, so staging and production move independently.

Release notes like this one live in the docs app and are optional by default — set the `REQUIRE_RELEASE_NOTE` repository variable to enforce them. Feature flags get a minimal convention (`isFeatureEnabled`) so two merged changes can ship separately without cherry-picking. On the boilerplate side, migration intentions are now written in the PR that introduces the change, and two intentions ("adopt conventional commits", "adopt release-please") guide existing projects through this upgrade.

Nothing breaks for existing projects: staying without versions is a supported mode, and the switch to versioning is a configuration change, whenever the team is ready.

The generated inventory is in `CHANGELOG.md`.
