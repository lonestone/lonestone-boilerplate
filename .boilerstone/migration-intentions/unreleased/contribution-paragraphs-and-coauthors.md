# Spell out the conventional paragraph format, validate PR descriptions locally, credit AI agents

## Goal

`CONTRIBUTING.md` says how a conventional paragraph must be laid out and asks for AI co-author trailers at the end of the description. The `finalize-pr` skill validates the description with `pnpm lint:pr` before applying it and keeps those trailers.

## Why

`scripts/lint-pr.ts` lints the first line of each conventional paragraph like a commit subject (100 characters at most, no trailing full stop). `CONTRIBUTING.md` never said that the explanation goes on the next lines, so writing it after the header on the same line is a natural reading that fails CI. The skill applied descriptions without running the check first. On a private repository on the GitHub free plan there is no branch protection, so a red PR lint does not block the merge: the local check is the only real gate.

Collaborators are entitled to know when code was generated by an AI agent: it changes how a change should be read and reviewed. With squash merges, trailers on branch commits are lost, so the PR description is the only place where that authorship survives. The general guidelines used to forbid Claude co-author trailers; that rule is removed.

## Applies When

- The project has `CONTRIBUTING.md` with the "Description" section from the boilerplate (rationale prose, then conventional paragraphs).
- The project has the `finalize-pr` skill under `.claude/skills/` and/or `.cursor/skills/`.
- The project has `scripts/lint-pr.ts` and a `lint:pr` script in the root `package.json`.

## Do Not Apply When

- The project does not use the boilerplate contribution system (no `CONTRIBUTING.md` Description section, no `finalize-pr` skill).
- A human has explicitly decided that AI agents must not be credited in commits after reviewing this intention. Then apply only gaps 1 and 3, and record the reason.

## Observable Gaps

1. **Paragraph format** — signal: `CONTRIBUTING.md` has no "**first line** of the paragraph is linted exactly like a commit subject".
   Add the paragraph and the `text` example under item 2 of the Description list, matching the staged reference.
   Done when: the sentence and the example are present under item 2.

2. **Co-author trailers** — signal: `CONTRIBUTING.md` has no "Co-author trailers, last" item; the project guidelines or agent instructions (`general.mdx`, `CLAUDE.md`, `AGENTS.md`, Cursor rules) still say not to co-author with an AI agent.
   Add item 3 from the staged reference. Remove the prohibiting rule wherever it appears.
   Done when: item 3 exists and `git grep -i "co-author with"` finds no prohibition.

3. **Local validation in finalize-pr** — signal: `finalize-pr/SKILL.md` ends its Job with `gh pr edit --title "..." --body "..."` and no `pnpm lint:pr` step.
   Replace the last step with the staged reference: validate with `pnpm lint:pr <event.json>`, apply with `--body-file`, then report the PR lint result.
   Done when: every copy of the skill has the `pnpm lint:pr` step.

4. **Trailers kept by finalize-pr** — signal: `finalize-pr/SKILL.md` has no `Co-Authored-By:` bullet under the description step.
   Add the bullet from the staged reference to every copy of the skill.
   Done when: every copy of the skill mentions keeping `Co-Authored-By:` trailers.

## Out of Scope

- `scripts/lint-pr.ts` and `commitlint.config.ts`: the lint rules do not change.
- The project's own types, scopes and other `finalize-pr` preflight steps.
- Git hooks and lefthook configuration.

## Validation

- `pnpm lint:pr <event.json>` on a description that ends with a `Co-Authored-By:` trailer passes.
- `pnpm lint:pr <event.json>` on a paragraph such as `fix(api): subject. Explanation…` on one line fails with `subject-full-stop` or `header-max-length`.
- The `.claude` and `.cursor` copies of `finalize-pr` are identical where they were before.
