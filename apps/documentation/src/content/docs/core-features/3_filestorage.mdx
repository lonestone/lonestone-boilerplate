---
title: File Storage
description: Store files in an S3-compatible bucket and serve them through signed URLs
---

Files live in an S3-compatible bucket: [RustFS](https://rustfs.com/) locally, any S3 provider in production. Storage is off by default, so a project without files never needs a bucket.

The [Posts example](https://github.com/lonestone/lonestone-boilerplate/tree/main/apps/api/src/modules/example/posts) uses it for an optional cover image.

# ❓ How it works

Two modules split the work:

- `StorageModule` moves bytes in and out of the bucket and signs download URLs. It knows nothing about the database.
- `MediaModule` owns the `media` table. One row is one stored file: its storage key, name, MIME type and size.

Your business module keeps the rest: routes, access rules, and the relation to `Media`.

The API never streams files. Each response that includes a file carries a signed URL that expires (one hour by default), and the browser loads the file straight from the bucket.

:::caution
Anyone holding a signed URL can read the file until it expires. Only map a `Media` for users allowed to see it.
:::

# 📝 How to use

Start RustFS with `pnpm docker:up`, then set `STORAGE_ENABLED=true` in `apps/api/.env`. The other `STORAGE_*` variables are listed in the [API README](https://github.com/lonestone/lonestone-boilerplate/blob/main/apps/api/README.md). The RustFS console runs on [http://localhost:9001](http://localhost:9001).

To attach a file to an entity:

1. Point to it with a relation, not with copied columns:

```typescript
@OneToOne(() => Media, { owner: true, nullable: true, fieldName: 'coverImageId' })
coverImage?: Media
```

2. Declare the file in the multipart contract. `z.file()` documents it in OpenAPI, so the generated SDK accepts a `File`:

```typescript
coverImage: z.file().max(10 * 1024 * 1024).optional()
```

For array fields, use `multipartArray(itemSchema)`: the controller gets a typed array, and the SDK takes one.

3. Add `@MultipartFile` on the route. It hands the uploaded file to `TypedMultipartBody` as a `File`, typed from its first bytes rather than from what the client claims:

```typescript
@TypedRoute.Post('', userPostSchema)
@MultipartFile('coverImage', { maxSize: 10 * 1024 * 1024 })
async createPost(@TypedMultipartBody(createPostSchema) body: CreatePostInput) {}
```

4. In the service, upload the file, attach it, then save. If the save fails, remove the uploaded file yourself:

```typescript
const media = this.mediaService.attach(await this.mediaService.upload(file))
post.coverImage = media
try {
  await this.em.flush()
} catch (error) {
  await this.mediaService.remove(media)
  throw error
}
```

When you replace or delete a media, call `em.remove(media)` before the flush and `mediaService.remove(media)` after it, so a failed save keeps the old file. `mediaService.remove` never throws: a failure only leaves an orphan in the bucket, and is logged.

5. In the mapper, `MediaMapper.toMedia` signs a URL. Reuse `mediaSchema` in your response contract.

On the frontend, pass the `File` to the SDK and put `coverImage.url` in an `<img>`. Refetch once `expiresAt` has passed.

:::note
While storage is disabled, uploads and any response that includes a file fail with `503`.
:::

# 🚀 Production

- Use a dedicated bucket and restricted credentials, and set `STORAGE_CREATE_BUCKET=false`.
- AWS S3 expects `STORAGE_FORCE_PATH_STYLE=false`.
- Browsers must reach the bucket at the `STORAGE_ENDPOINT` host, because the host is part of the signature. A private hostname, like a Docker service name, gives URLs that browsers cannot open.

# 🗑️ How to remove

Leave `STORAGE_ENABLED=false` if you only want it off. To remove it entirely:

1. Remove the `coverImage` relation from posts and create a migration that drops the `media` table.
2. Delete `apps/api/src/modules/media` and `apps/api/src/modules/storage`.
3. Remove `@aws-sdk/client-s3`, `@aws-sdk/s3-request-presigner`, `@types/multer` and `testcontainers` if nothing else uses them.
4. Remove the `STORAGE_*` variables and the RustFS service and volume from Docker Compose.
5. Regenerate the OpenAPI client.
