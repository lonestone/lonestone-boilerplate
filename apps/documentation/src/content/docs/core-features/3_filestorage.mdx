# File Storage

The API includes provider-neutral S3 infrastructure and an optional Documents example. Storage is
disabled by default, so an unavailable S3 service cannot prevent an application that does not use
files from starting.

`StorageModule` is infrastructure-only. It exports `StorageService`, uses one default bucket, and
does not expose HTTP routes or provider internals. Business modules own their HTTP contracts,
authorization rules, and database metadata.

## Configuration

Configure the API with these provider-neutral variables:

- `STORAGE_ENABLED`: register the Documents example and its storage infrastructure. Defaults to
  `false`.
- `STORAGE_BUCKET`: default bucket name.
- `STORAGE_ENDPOINT`: S3 endpoint. Use the provider endpoint in production.
- `STORAGE_REGION`: S3 region.
- `STORAGE_ACCESS_KEY_ID` and `STORAGE_SECRET_ACCESS_KEY`: provider credentials.
- `STORAGE_FORCE_PATH_STYLE`: required by many self-hosted S3-compatible services.
- `STORAGE_CREATE_BUCKET`: create the default bucket during startup when storage is enabled and the
  bucket is missing.
- `STORAGE_MAX_UPLOAD_SIZE`: maximum HTTP upload size in bytes.

## Local RustFS

Docker Compose provides RustFS as the local S3-compatible service. Its data is stored in the
`rustfs_data` volume.

```bash
pnpm docker:up
```

The default S3 endpoint is `http://localhost:9000`. The RustFS console is available at
`http://localhost:9001`. Credentials come from the root `.env` file and are mapped to RustFS by
Compose.

## Use from API code

Inject `StorageService` into another NestJS service. Business modules should depend on this
service instead of importing the AWS SDK or the S3 provider.

```typescript
@Injectable()
export class DocumentsService {
  constructor(private readonly storageService: StorageService) {}

  async save(file: Buffer): Promise<string> {
    const object = await this.storageService.upload({
      body: file,
      filename: 'document.pdf',
      mimeType: 'application/pdf',
      size: file.byteLength,
    })

    return object.key
  }
}
```

Store the returned opaque key in a business entity when the file belongs to a domain concept. Do
not expose that key as the public resource identifier. The Documents example shows this pattern.

## Documents example

Set `STORAGE_ENABLED=true` to register the example. Authenticated clients can upload one multipart
`file`, then download or delete it by document ID under `/api/documents`. The `Document` entity
stores the owner, storage key, original filename, MIME type, and size.

Every read and delete includes the authenticated owner in the database query. A different user
receives `404`, which does not reveal whether the document exists. If the metadata transaction
fails after upload, the service deletes the uploaded object as compensation.

The generated SDK builds `FormData` for uploads and returns a `Blob` for downloads:

```typescript
const upload = await documentControllerUpload({
  body: { file },
})

const download = await documentControllerDownload({
  path: { id: upload.data.id },
})
```

Use the example as a starting point for domain-specific modules such as invoices, profile images,
or attachments. Keep storage mechanics in `StorageService`, but put access rules and routes in the
domain module.

## Production

Use a dedicated bucket and restricted credentials. Disable automatic bucket creation after
provisioning infrastructure. Configure the provider endpoint, region, TLS, retention, backups,
and lifecycle rules according to the chosen service. Set a size limit that also matches reverse
proxy and platform limits.

AWS S3 normally uses virtual-hosted addressing, so set `STORAGE_FORCE_PATH_STYLE=false`. Keep it
enabled only when the selected compatible provider requires it.

## Remove storage

Delete `apps/api/src/modules/example/documents` and remove `DocumentModule` from `ExampleModule`.
Then delete `apps/api/src/modules/storage`, the document migration and snapshot entry, and the AWS
SDK, direct `testcontainers`, and Multer type dependencies if nothing else uses them. Remove the
`STORAGE_*` variables, the RustFS Compose service and volume, then regenerate the OpenAPI client.
